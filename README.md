# tab-trader

**Can a pretrained tabular model price a Bitcoin binary better than the crowd, on a CPU?**

This repo is a TabPFN-3.5 Hackathon project. It tests **TabPFN-3.5**, untuned and running on an ordinary 8-core CPU, against
**six tuned classic learners** (logistic regression, random forest, XGBoost, LightGBM, CatBoost, MLP) and against
**the market's own price**. The task is forecasting how Kalshi's recurring Bitcoin contracts settle. Two markets are covered:

* **KXBTC15M**: "Will BTC be higher at the end of this 15-minute window?" (96 new markets a day)
* **KXBTCD**: "Will BTC be above $K at the top of the hour?" (an hourly ladder of strikes)

The data is my own. My collectors have recorded these markets about four times a second since **21 March 2026**:
roughly 245 million rows of market tape, order book, exchange spot, derived indicators and settlement-index prints. None of it can be downloaded after the fact.

📊 **Interactive write-up:** https://cloblak.github.io/tab-trader/ (source: [`docs/index.html`](docs/index.html))

## How TabPFN-3.5 is used

| Where | Variant | How |
|---|---|---|
| Main benchmark | **TabPFN-3.5** (open weights) on CPU | `TabPFNClassifier.create_default_for_version(ModelVersion.V3_5, device="cpu", fit_mode="fit_with_cache")`, refit every week on the latest 5,000 rows, never tuned |
| Main benchmark | **TabPFN-3.5-Fast** on CPU | same API, `ModelVersion.V3_5_FAST` |
| Extra row | **TabPFN-3.5 Thinking** via the Prior Labs API | `tabpfn_client.TabPFNClassifier(thinking_mode=True, thinking_effort="high", time_col="decision_epoch_s")` |
| Live-scoring latency | KV cache (`fit_with_cache`) | fit once per week, then score a single live market on CPU |
| My own strategy (section 7) | TabPFN-3.5 as the trade filter | scores 1,494 out-of-sample signals from my live strategy; features withheld, predictions published |

## What makes the comparison fair

* **Pre-registered.** [`PREREG.md`](PREREG.md) fixes the split, models, metric and decision rule. It was committed before any test fold ran.
* **Walk-forward.** Weekly test blocks; every model trains only on markets that closed before the block starts.
* **Equal context.** Every model gets the same 5,000 rows (TabPFN-3.5's default CPU limit). A second policy gives the
  classic models *all* history while TabPFN stays at 5,000.
* **Classic models are tuned; TabPFN is not.** Each classic model keeps the better of its library defaults and a
  20-configuration random search on a validation slice.
* **The market is a competitor.** A contract's price is already a forecast, so every table includes it.
* **Clean, point-in-time data.**
  * Every decision is priced at a single instant from collector-validated, uncrossed quotes at most 5 s old.
  * Every quote is cross-checked against Kalshi's own 1-minute candle.
  * BTC features use only bars that had closed by the decision time.
* **Controls.** A planted signal must be found by every model. Under a calibrated-market null, no model may "beat" the market.
* **Uncertainty.** Day-block bootstrap 95% CIs on paired differences, with Benjamini–Hochberg across comparisons.

## Reproduce

```bash
git clone https://github.com/Cloblak/tab-trader && cd tab-trader
uv sync                          # Python 3.12; CPU-only torch
export TABPFN_TOKEN=...          # free: https://ux.priorlabs.ai (accept the TabPFN-3.5 licence)
make quick                       # one test week per market, all models, about 10 min on 8 cores
make benchmark                   # full walk-forward + learning curves (hours; resumable)
make thinking                    # optional: TabPFN-3.5 Thinking via the API (uses API credits)
make controls analyze report notebooks verify
```

`make analyze report notebooks verify` alone rebuilds every number and chart from the committed predictions.

## Notes and limits

* The data in this repo was recorded by the author from Kalshi's public market data and public BTC spot feeds. The full
  tape stays private. What is published is enough to reproduce every result.
* Generic momentum features carry very little information beyond the price. Treat the trading tables as descriptive,
  not as a strategy.
* Section 7's test blocks were reused across the author's earlier experiments. A forward test is the next step.
* The TabPFN-3.5 open weights are licensed for evaluation and internal benchmarking. Live trading with them would need a
  commercial licence or the Prior Labs API.
